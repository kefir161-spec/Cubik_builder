## Для HR и рекрутера (коротко)

| Вопрос | Ответ |
|--------|--------|
| **Что это** | Браузерный 3D-редактор для сборки модульного продукта: визуализация, правила сборки, сохранение конфигурации, связка с заказом и производством. |
| **Зачем компании** | Self-service конфигуратор: меньше ручной работы менеджеров, выше вовлечённость клиента, предсказуемый экспорт в заказ. |

Остальные проекты на профиле (корпоративная платформа, лендинг, мобильные приложения и т.д.) — **отдельные продукты**, к коду редактора не относятся.

## Что умеет продукт

- **Интерактивный 3D-редактор (WebGL):** сцена в реальном времени, управление объектами в браузере  
- **Параметрическая конфигурация:** логика модульной сборки, ограничения, редактируемые параметры  
- **UI вокруг 3D:** панели, контролы, состояния, онбординг  
- **Проект и сохранение:** сериализация сцены, загрузка конфигураций  
- **Undo / Redo** и **autosave**  
- **Интеграция с продажами и производством:** маппинг конфигурации к SKU, превью (thumbnails), при необходимости экспорт артефактов (например PDF-инструкции)

## Сильные стороны и сложность (для глубокого интервью)

- **Сложный клиентский продукт:** не «страница с 3D», а редактор с состоянием, историей действий и устойчивостью к ошибкам загрузки/сериализации  
- **Связка UX + WebGL:** понятный UI при нагруженной сцене и множестве сценариев  
- **Производственный контекст:** конфигурация должна быть согласована с реальными модулями и ограничениями  
- **Итеративная эволюция:** видна по цепочке версий выше — от раннего редактора до текущего билдера с полным набором функций

## Моя роль / зона ответственности

**Полная end-to-end разработка (solo):**

- идея и продуктовая концепция  
- архитектура фронтенда и реализация  
- **UX/UI редактора** (сценарии, взаимодействия, структура интерфейса)  
- **вёрстка и стилизация UI (HTML/CSS):** лэйаут, адаптивность, состояния, компоненты  
- рендер-пайплайн и оптимизация производительности  
- интеграции с backend API (сохранение/загрузка, экспорт, заказ)  
- тестирование и итеративное развитие  

Дополнительно:

- участие в обсуждении product roadmap  
- постановка задач и контроль **рендеров новых продуктов** у дизайнеров  
- проверка **технической корректности 3D-моделей** и соответствия производственным ограничениям

## Технологии

- **HTML, CSS** (адаптивная вёрстка, UI вокруг canvas/WebGL)  
- **JavaScript**  
- **WebGL / Three.js** (в сборке — CDN Three.js r128, модули сцены/контролов/экспорта)  
- интеграции с **REST API**  
- сериализация и сохранение состояния на клиенте  
- современные практики разработки, в т.ч. AI-ассистирование для ускорения итераций (прототип → production)

## Структура проекта (ключевые модули)

> Названия файлов могут меняться между сборками; логика разбита по зонам:

- `renderer.*` — сцена, камера, рендер-цикл, загрузчики, материалы, оптимизация  
- `ui.*` — UI редактора, события  
- `history.*` — undo/redo  
- `autosave.*` — автосохранение и восстановление  
- `io.*` — импорт/экспорт, сериализация  
- `backend-api.*` — слой API  
- `thumbnail.*` — превью  
- `pdf-instructions.*` — экспорт инструкций (если включено)  
- `tutorial.*` / `mobile.*` — онбординг и мобильная адаптация  

Подробности отдельных исправлений см. [CHANGELOG.md](./CHANGELOG.md).

## Зачем это бизнесу

Конфигуратор работает как **инструмент продаж и самообслуживания**:

- выше конверсия за счёт интерактива и персонализации  
- меньше ручной работы пресейла и менеджеров  
- предсказуемая передача конфигурации в заказ и производство
